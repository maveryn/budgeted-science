# Fixed two-check numerical verification baseline

Run September 11, 2026, on the existing 30-study development catalog. No
studies were regenerated, excluded, or replaced. These variants share six
underlying systems; this is not held-out or general scientific-verification
performance.

## Method

Read the original peak from the public analysis artifact, refine integration
(3 credits), then refine sampling on that purchased run (2 credits).
Submit ACCEPT when
`abs(Q_reported - Q_refined) / abs(Q_refined) <= 0.05`, otherwise REJECT.
An unavailable required check produces ABSTAIN; execution errors remain
incomplete.

The policy receives only the public tool-call interface. It cannot access
parameters, private reference trajectories, labels, or evaluator results.
The harness scores the actual submitted verdict afterward. Unlike the earlier
scripted fixtures, the answers are computed from purchased evidence.

This is a task-specific numerical verifier. It reads the known structured
analysis field, rather than interpreting arbitrary free-form reports.
The combined check is an approximate numerical comparison, not a certified
error bound.

## Interpretation

The toy is solvable by a fixed workflow when both checks fit the budget.
This is a useful numerical sanity check and a comparison for a future agent,
but it does not demonstrate that adaptive auditing is needed. The cases have
clear margins around the 5% threshold, the same claim family, and a known
structured result field. Do not extrapolate this result to arbitrary reports,
other scientific claims, or tighter resource constraints.
